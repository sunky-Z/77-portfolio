# 77 个人站 · 设计规范 v1

当前方案采用已选的编辑式布局与橙色强调，依据[选定参考稿](design/selected-direction-v1.png)。这是可继续调整的工作版本，不是固定的品牌规范。后续根据真实内容、设备表现和阅读反馈修改，以已确认的文案和可用性为准。

参考稿展示首页及一个项目详情开头；其余页面沿用同一套字体、间距、分隔和交互规则。栅格、文字和流程由前端实现，参考图片不作为整页背景使用。

## 目标与层级

让第一次访问的人先看懂 77 的职业方向，再按兴趣了解经历、项目和能力。HR 从经历与教育开始；业务负责人从项目进入具体判断和交付；其他访客从简介与精选项目认识 77。

保留“首页 → 分类总览 → 详细正文”三层、19 个独立页面及未找到页面。概括内容使用卡片或轻量入口；详细内容用完整正文说明背景、判断、动作、交付和职责边界。主导航打开独立网址，页内目录只定位当前正文。

## 配色

白色为主底，黑灰承担文字、线条和图像。橙色集中在主要操作、首页眉题、少量交付数字及必要状态提示，参考面积控制在页面的 3–5% 以内。不要给大标题、大面积底色、所有链接和全部图标统一着色。

色彩变量位于 `src/styles.css`：

```css
--accent: #C25428;
--accent-hover: #A74420;
--accent-soft: #FFF2EA;
--ink: #171717;
--muted: #686868;
--line: #e5e5e5;
--soft: #f7f7f7;
```

| 用途 | 规则 |
|---|---|
| 主要按钮 | 橙底白字；悬停使用 `--accent-hover` |
| 重点数字 | 白底橙字，保留完整对象和单位 |
| 详情事实条 | 浅灰底上的小号数字使用 `--accent-hover`，对比度约 5.62:1 |
| 浅橙提示底 | 使用 `--accent-soft`，搭配深色文字 |
| 正文与标题 | `--ink`；不要将整段正文改成橙色 |
| 次要文字 | `--muted`，保留可读性 |
| 分隔 | 1px `--line`，优先于阴影和厚边框 |
| 次要分组底 | `--soft`，避免重复套卡片 |

`#C25428` 与白色的对比度约为 4.57:1，适合当前按钮与短数字文字。浅橙底不使用小号橙字。更换强调色时，连同按钮文字色、悬停色、浅底和焦点状态一起检查，不只替换一个色值。

## 字体与文字

中文使用 Apple 中国站风格的本机无衬线字体，英文和数字继续优先使用本机 Times New Roman。`src/fonts.css` 将 Times 本机字体声明为 `Portfolio Times`，并用 `unicode-range` 限制在拉丁字符、数字及相关符号范围；斜体单独匹配本机 Times 斜体。这样可避免操作系统的 Times 字体链接将中文选成衬线体。当前字体栈为：

```css
'Portfolio Times', 'SF Pro SC', 'PingFang SC',
'Hiragino Sans GB', 'Microsoft YaHei', 'Noto Sans CJK SC',
'Noto Sans SC', sans-serif
```

`Portfolio Times` 依次读取本机 Times New Roman、Times 或 Liberation Serif；中文由后续无衬线字体承担。工程不打包字体二进制文件，也不分发 Apple 字体文件；Windows 通常回退到 Microsoft YaHei，其他设备可使用 Noto 或系统无衬线字体，因此不同系统的字宽与换行会略有差异。不得为了模仿参考图的栅格文字，把中文标题统一改成衬线体。

大标题清楚、简短；中文标题不用密集字距。正文以 16–18px 为主要范围，行高约 1.8–1.95，避免过长行宽。英文眉题可使用 Times 斜体；它用于标记章节，不能取代清楚的中文标题。

首页简介保留三段，末尾不加标点：

```text
心理学本科，工商管理硕士，ENFJ
关注人机交互与商业化，职业经历涵盖用户研究、产品与 GTM 策略
现从事 AI 产品经理
```

全站文案采用短标题、重点摘要、事实正文的顺序。写清具体工作和产物，少用口语化引导、泛化口号和未经证实的成绩。修改中文后同时核对英文的职责范围和事实限定。

## 首页

1. 顶部保留 77 标识、经历／项目／能力／联系导航，以及右上角语言按钮。
2. 首屏左侧放眉题、两行标题、三段简介和操作；右侧使用独立的个人概括线稿。“浏览项目”为主要操作，“职业经历”为次要操作。
3. 首屏下方用轻量横向章节入口连接经历、项目和能力，以留白及细分隔组织，不再堆放三张大入口卡。
4. 精选项目采用一个主项目与两个次项目：主项目在左，较大的封面和标题；两个次项目在右纵向排列，封面与文字并置。两列约等宽，以细线分隔，不把每个项目装进厚重盒子。
5. 主项目为“主动服务与 AI 任务体验”，次项目为“AI 技能发现与质量治理”“AI 订阅与权益体系”。保留摘要、限定数字与明确的项目链接。
6. 底部保留轻量联系入口及页脚，避免额外增加介绍模块。

## 分类与正文

分类页继续用统一概括卡片组织职业经历、七个项目及四个能力分支。卡片包含标题、简述和去向；项目卡片可带概念图和交付事实。不要把全文塞进分类卡片。

正文从面包屑、标题、工作范围和简述开始，返回操作明确指向父分类。主要内容直接排在页面上，以章节、留白和细线建立阅读节奏；产物列表和相关入口可以使用浅底或轻边框。

“主动服务与 AI 任务体验”的首个关键判断采用左文右流程：左侧解释“展示与执行分别管理”，右侧标明“交互流程示意”，展示任务发起、执行中、用户确认、查看结果，并区分停止展示与停止执行。流程使用语义列表、真实文字和现成图标，不能作为真实产品截图或已验证用户旅程呈现。

其他判断、主要工作、交付进展、相关项目与能力继续完整展开。无相应材料的项目不补造同样数量的判断或成果。项目页的目录位于开篇判断之后，横向排列并可换行；经历与能力正文在桌面使用侧栏目录，850px 及以下移到正文末尾，以可换行的横向目录呈现。目录不替代独立页面导航。

## 间距与响应式

页面以居中内容宽度、左右留白和稳定的章节间距组织。优先用对齐和留白，其次用细线，再按需使用浅底、边框；不使用装饰性发光、渐变或明显阴影。

| 视口 | 布局要求 |
|---|---|
| 大于 1100px | 保留宽松左右留白；首屏与精选项目双栏；正文与辅助目录分开 |
| 851–1100px | 缩小列距和侧边距，保持主要文字与图像的比例 |
| 621–850px | 优先保证阅读宽度；精选主次关系转为纵向顺序，经历与能力目录移到末尾横向排列并允许换行 |
| 361–620px | 首屏、项目和正文转为单列；任务流程按步骤纵向排列；语言按钮保持可见，主导航使用菜单；左右至少约 20px |
| 不大于 360px | 左右约 16px，适度减小标题，控制按钮和长链接的换行 |

断点用于解决内容拥挤，可随实际页面调整。手机依次呈现简介、首屏图、章节入口和精选项目；不得通过隐藏正文或裁切重要图像来消除溢出。长英文标题、邮箱、标签及中英切换后均应可读，横向不溢出。

## 图像与图标

复用现有个人概括线稿、项目线稿和三个概念 SVG，维持白底、稀疏黑线与通用成年男性形象。首页概括图与项目封面分别使用素材；人物不作为真实肖像，概念图不作为产品截图。

参考稿中机器人的橙色小块不是必要资产改动，当前黑色线稿可以保留。常规操作及流程图标使用 `@phosphor-icons/react`，统一细线风格和尺寸；正文流程的文字与顺序保留为可访问的 HTML。装饰图留空替代文字，承载信息的图像提供相应说明。

## 交互与可访问性

所有导航、卡片和相关入口都要有真实链接。切换中英文保留所在页面和阅读位置，并记住本机偏好；手机菜单的开合状态清楚。复制邮箱提供成功或失败反馈，邮箱本身仍可直接使用。

按钮、链接和菜单支持键盘操作；焦点清晰，不只通过颜色表示当前状态。主要点击目标约 40–44px 或以上。交互以轻量颜色、边框反馈为主；尊重减少动态效果设置，不加入影响阅读的入场和滚动动效。

## 公开内容的事实限定

数字必须连同对象、阶段和状态保留，不改写为业务结果：

- 29 套卡片模板、38 个视觉变体属于设计交付
- 295 → 47 属于共享标签体系整理
- 15 类账户场景属于订阅原型覆盖，不等于真实支付全部通过
- 19 条技能 × 46 个语言配置属于内容配置，不等于覆盖 46 个国家
- 不加入缺少完整口径的留存、收入或转化提升指标

不补充内部平台项目或新的 GTM 经历；原有简介提及的 GTM 策略保留。公开工程只放可发布的网站内容和素材，私人档案、简历原件与核对资料不随站点发布。

## 后续修改与验收

先修改 `src/styles.css` 中的变量，再核对组件状态；修改结构时同步更新本规范。参考图用于判断比例与节奏，准确文案和字体以源码及本规范为准。

每轮交付至少核对首页、项目分类、一个详细项目和联系页的中英文与手机布局；路由和资源检查覆盖全站。运行 `npm test`、`npm run build`、`npm run check:build`，再检查独立链接、刷新、返回、语言和菜单。视觉对照结果记录在 `design-qa.md`，未解决的明显溢出、断链或阅读问题应先修复。
